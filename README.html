Cible et portée

Ce projet est conçu pour fonctionner intégralement sur le poste de travail d'un membre de l'équipe SPM B2B BE — pas de serveur, pas de cloud, pas d'infrastructure partagée.

Tout est local par défaut :

  • Téléchargement des images satellite → dossier data/raw/ sur le disque
  • Stockage métadonnées + features + prévisions → fichier SQLite data/solar_forecast.db
  • Entraînement du modèle XGBoost → CPU local, modèle sauvé dans models/xgboost_v1.pkl
  • Inférence + API → FastAPI sur http://127.0.0.1:8000
Aucune installation de PostgreSQL, Docker ou outil tiers n'est requise pour le mode local. Voir §10 pour les modes optionnels (Postgres, Docker).

Target audience & scope

This project is designed to run entirely on a single SPM B2B BE team-member's workstation — no server, no cloud, no shared infrastructure.

Everything is local by default:

  • Image download → data/raw/ on the local disk
  • Storage of metadata + features + forecasts → SQLite file data/solar_forecast.db
  • Model training → local CPU, model saved to models/xgboost_v1.pkl
  • Inference + API → FastAPI on http://127.0.0.1:8000
No PostgreSQL, Docker, or third-party install required for the local mode. See §10 for optional modes (Postgres, Docker).

4. Base SQLite — initialisation

Une seule commande crée le fichier data/solar_forecast.db et toutes les tables :

python main.py init-db

Tables créées :

  • satellite_images — métadonnées des tuiles téléchargées
  • cloud_features — cloud index + flot optique par zone
  • weather_data — variables NWP Open-Meteo
  • solar_forecasts — prévisions produites par le modèle
Aucun serveur à lancer. SQLite est un simple fichier sur le disque, géré par la bibliothèque standard Python.

5. Workflow local complet — du clone à la prévision

Procédure complète pour un membre de l'équipe SPM B2B BE qui démarre de zéro.

① Initialiser la base SQLite 
python main.py init-db
② Backfill météo — 90 derniers jours 
python main.py backfill

Télécharge l'historique Open-Meteo pour les 8 zones (~17 000 lignes en quelques minutes).

③ Télécharger les images satellite

Deux options :

# Option A — un seul round (test)
python main.py scrape-once

# Option B — boucle continue (laisser tourner en arrière-plan)
python main.py scrape

Les tuiles JPEG arrivent dans data/raw/visible/<timestamp>/ et data/raw/infrared/<timestamp>/. La nuit, le canal VIS est automatiquement sauté (fallback IR + NWP).

④ Calculer les features (cloud index + flot optique) 
python main.py worker

Traite toutes les images marquées processed=False et insère les features en base.

⑤ Entraîner le modèle XGBoost 
python main.py train

Entraîne un modèle par horizon (H+1, H+3, H+6, H+12, H+24, H+48) sur les features collectées. Affiche MAE, RMSE et skill score vs NWP. Le modèle est sauvé dans models/xgboost_v1.pkl.

Attention : il faut au minimum quelques jours de scrape pour avoir assez de features. En dessous de 7 jours de données, l'entraînement échouera ou donnera de très mauvais scores.
⑥ Lancer l'API d'inférence en local 
python main.py serve

Ouvre http://127.0.0.1:8000/docs pour tester l'API en interactif.

⑦ (Recommandé) Lancer l'orchestrateur tout-en-un 
python main.py scheduler

Un seul process qui orchestre scrape (15 min), météo (1 h), worker (15 min) et prévision (à HH:05). À combiner avec python main.py serve dans un second terminal.

5. Full local workflow — from clone to forecast

End-to-end procedure for an SPM B2B BE team-member starting from scratch.

① Initialise the SQLite database 
python main.py init-db
② Weather backfill — last 90 days 
python main.py backfill

Downloads Open-Meteo history for the 8 zones (~17,000 rows, takes a few minutes).

③ Download satellite images

Two options:

# Option A — single round (test)
python main.py scrape-once

# Option B — continuous loop (leave running in the background)
python main.py scrape

JPEG tiles land in data/raw/visible/<timestamp>/ and data/raw/infrared/<timestamp>/. At night the VIS channel is automatically skipped (IR + NWP fallback).

④ Compute features (cloud index + optical flow) 
python main.py worker

Processes every image marked processed=False and inserts the features into the DB.

⑤ Train the XGBoost model 
python main.py train

Trains one model per horizon (H+1, H+3, H+6, H+12, H+24, H+48) on collected features. Prints MAE, RMSE, and skill score vs NWP. Model is saved to models/xgboost_v1.pkl.

Heads-up: you need at least a few days of scrape to gather enough features. With less than 7 days of data, training will fail or score very poorly.
⑥ Start the local inference API 
python main.py serve

Open http://127.0.0.1:8000/docs to test the API interactively.

⑦ (Recommended) Run the all-in-one orchestrator 
python main.py scheduler

A single process orchestrating scrape (15 min), weather (1 h), worker (15 min) and forecast (at HH:05). Pair with python main.py serve in another terminal.

7. API REST locale

Une fois python main.py serve lancé, l'API tourne sur http://127.0.0.1:8000.

MéthodePathDescription
GET/healthStatut système (fraîcheur scrape, météo, modèle)
GET/zonesListe des zones configurées
GET/forecast/{zone}Prévision 48 h pour une zone
GET/forecast/{zone}/{horizon_h}Point unique pour un horizon
POST/forecast/triggerLance une nouvelle prédiction pour toutes les zones

Exemples curl

# Santé du système
curl http://127.0.0.1:8000/health

# Lister les zones
curl http://127.0.0.1:8000/zones

# Prévision Bruxelles 48 h
curl http://127.0.0.1:8000/forecast/brussels

# Prévision Paris-Nord à H+6
curl http://127.0.0.1:8000/forecast/paris_nord/6

# Forcer une nouvelle prévision
curl -X POST http://127.0.0.1:8000/forecast/trigger

Zones disponibles : brussels, liege, ghent, amsterdam, paris_nord, luxembourg, cologne, lille.

8. Tuning Optuna (optionnel)

# 50 essais sur l'horizon H+1
python main.py tune

# 100 essais sur l'horizon H+6
python main.py tune --horizon 6 --trials 100

Le tuning utilise une cross-validation walk-forward à 3 folds (pas de fuite temporelle). Le modèle final est sauvé dans models/xgboost_v1_tuned.pkl.

Charger un modèle dans son code :

from model.trainer import load_models
models = load_models("v1_tuned")   # dict[horizon_h, XGBRegressor]
y_pred = models[6].predict(X)      # prévision H+6

9. Dépannage

python main.py train renvoie « No training data »

  • Faire d'abord python main.py backfill (météo) puis attendre que le worker ait traité au moins une journée d'images.
  • Vérifier que la base contient des features : 
    sqlite3 data/solar_forecast.db "SELECT COUNT(*) FROM cloud_features;"

L'API renvoie « No forecast available »

  1. Vérifier qu'un modèle existe dans models/.
  2. Lancer POST /forecast/trigger ou attendre HH:05 si le scheduler tourne.
  3. Consulter GET /health pour identifier le champ manquant.

Le scrape échoue avec 403 ou 429

  • Vérifier que SAT24_MIN_REQUEST_INTERVAL_S ≥ 5 s (défaut OK).
  • Patienter quelques minutes — le rate-limit Infoplaza est temporaire.

Erreur OpenCV au démarrage (Linux)

Installer libgl1 et libglib2.0-0 :

sudo apt-get install libgl1 libglib2.0-0

Inspecter la base SQLite

Avec n'importe quel outil SQLite (DB Browser for SQLite, DBeaver, ligne de commande) :

sqlite3 data/solar_forecast.db
sqlite> .tables
sqlite> SELECT * FROM solar_forecasts ORDER BY produced_at DESC LIMIT 10;

Logs

Format global défini dans main.py — passer logging.basicConfig(level=logging.DEBUG, ...) pour plus de verbosité.

9. Troubleshooting

python main.py train returns "No training data"

  • Run python main.py backfill (weather) first, then wait for the worker to process at least one day of images.
  • Check the DB has features: 
    sqlite3 data/solar_forecast.db "SELECT COUNT(*) FROM cloud_features;"

The API returns "No forecast available"

  1. Check that a model exists under models/.
  2. Run POST /forecast/trigger or wait until HH:05 if the scheduler is on.
  3. Look at GET /health to spot the missing component.

Scrape fails with 403 or 429

  • Confirm SAT24_MIN_REQUEST_INTERVAL_S ≥ 5 s (default is fine).
  • Wait a few minutes — Infoplaza rate-limits are temporary.

OpenCV startup error (Linux)

Install libgl1 and libglib2.0-0:

sudo apt-get install libgl1 libglib2.0-0

Inspect the SQLite database

Use any SQLite tool (DB Browser for SQLite, DBeaver, command line):

sqlite3 data/solar_forecast.db
sqlite> .tables
sqlite> SELECT * FROM solar_forecasts ORDER BY produced_at DESC LIMIT 10;

Logs

Global format set in main.py — switch to logging.basicConfig(level=logging.DEBUG, ...) for more verbosity.

10. Modes optionnels (avancés)

Mode PostgreSQL / TimescaleDB

Pour une base partagée entre plusieurs membres de l'équipe ou des volumes plus importants, basculer sur PostgreSQL :

# 1. Créer la base et l'extension
createdb solar_forecast
psql -d solar_forecast -c "CREATE EXTENSION IF NOT EXISTS timescaledb;"

# 2. Appliquer le schéma optimisé
psql -U <user> -d solar_forecast -f db/schema.sql

# 3. Modifier .env
DATABASE_URL=postgresql://user:password@localhost:5432/solar_forecast

Mode Docker Compose

Pour une stack reproductible (Postgres + scheduler + API), un docker-compose.yml est fourni :

cp .env.example .env
docker compose up -d --build
curl http://localhost:8000/health
Sécurité : changer impérativement POSTGRES_PASSWORD dans docker-compose.yml avant tout déploiement hors machine locale.
