1. Prérequis

  • Python 3.11+ (le projet utilise les annotations X | Y)
  • PostgreSQL 14+ (idéalement avec l'extension TimescaleDB)
  • Git pour cloner le dépôt
  • Optionnel mais recommandé : Docker + Docker Compose pour un déploiement clé en main
  • Une connexion internet (sat24.com + api.open-meteo.com)
Remarque : aucune clé API n'est requise — Open-Meteo fonctionne en accès libre dans la limite de ~10 000 requêtes/jour, et sat24 ne demande pas d'authentification (mais lire les CGU avant tout usage commercial).

2. Installation

Étape 1 — Cloner le dépôt 
git clone https://github.com/regiscop/cloudcoveragewebscraper.git
cd CloudCoverageWebScraper
Étape 2 — Créer un environnement virtuel 
python -m venv .venv
source .venv/bin/activate          # Linux / macOS
# .venv\Scripts\activate          # Windows PowerShell
Étape 3 — Installer les dépendances 
pip install -r requirements.txt

Inclut : requests, Pillow, opencv-python, numpy, openmeteo-requests, pvlib, xgboost, optuna, sqlalchemy, psycopg2-binary, fastapi, uvicorn, APScheduler, pandas, python-dotenv.

3. Configuration

Le projet utilise un fichier .env pour les paramètres sensibles.

Copier le modèle d'environnement 
cp .env.example .env

Variables disponibles (toutes ont une valeur par défaut dans config.py) :

VariableDéfautDescription
DATABASE_URLpostgresql://user:password@localhost:5432/solar_forecastURL SQLAlchemy de la DB
SCRAPE_INTERVAL_MINUTES15Intervalle entre deux rounds de scrape
DATA_DIRdata/rawRépertoire de stockage des tuiles JPEG
API_HOST0.0.0.0Host d'écoute FastAPI
API_PORT8000Port d'écoute FastAPI
OPENMETEO_CACHE_TTL3600TTL du cache Open-Meteo en secondes
Personnalisation : les zones géographiques (GRID_POINTS), les tuiles sat24 (TILES), les variables NWP (OPEN_METEO_VARIABLES) et les horizons (FORECAST_HORIZONS_H) se modifient directement dans config.py.

4. Initialisation de la base de données

Option A — TimescaleDB (recommandé)

Profite des hypertables pour un stockage et des requêtes time-series optimisés.

# Créer la base et un user
createdb solar_forecast
psql -d solar_forecast -c "CREATE EXTENSION IF NOT EXISTS timescaledb;"

# Appliquer le schéma
psql -U <user> -d solar_forecast -f db/schema.sql

Option B — PostgreSQL standard ou SQLite

Crée les tables via SQLAlchemy (sans hypertables).

python main.py init-db
Attention : sans TimescaleDB les requêtes sur de longs historiques seront plus lentes, et le stockage n'est pas compressé.

5. Commandes CLI

Toutes les commandes passent par python main.py <command>.

CommandeDescription
scrapeBoucle bloquante — fetch les tuiles sat24 toutes les SCRAPE_INTERVAL_MINUTES
scrape-onceUn seul round de scrape (utile pour cron / tests)
fetch-weatherRécupère les prévisions Open-Meteo pour toutes les zones et insère en DB
backfillBackfill des 90 derniers jours de données NWP archive
workerTraite les images processed=False → cloud index + flot optique
trainEntraîne XGBoost multi-horizons à partir des features & météo en DB
tuneTuning Optuna walk-forward (--horizon N --trials M)
schedulerDémarre l'orchestrateur APScheduler (tous les jobs en un process)
serveDémarre l'API FastAPI sur API_HOST:API_PORT
init-dbCrée les tables via SQLAlchemy (alternative à schema.sql)

Quick start — première utilisation

Étape 1 — Initialiser la DB 
python main.py init-db
Étape 2 — Backfill météo (90 jours d'historique) 
python main.py backfill
Étape 3 — Démarrer la collecte des tuiles satellites 
# En boucle (laisser tourner) :
python main.py scrape

# OU un seul round (pour tester) :
python main.py scrape-once
Étape 4 — Lancer le worker de feature engineering 
python main.py worker
Étape 5 — Entraîner le modèle (après quelques jours de scrape) 
python main.py train

Affiche les MAE / RMSE / skill score par horizon. Le modèle est sauvegardé dans models/xgboost_v1.pkl.

Étape 6 — Démarrer l'API 
python main.py serve
# → http://localhost:8000/docs (Swagger UI)

Mode tout-en-un — APScheduler

Pour tout orchestrer dans un seul processus (scrape + météo + features + trigger forecast) :

python main.py scheduler
  • Scrape toutes les SCRAPE_INTERVAL_MINUTES (défaut 15 min)
  • Worker de features toutes les 15 min
  • Fetch Open-Meteo à chaque heure pile
  • Trigger d'une prévision fraîche à HH:05

6. API REST

Une fois python main.py serve lancé, ouvrez http://localhost:8000/docs pour la documentation interactive Swagger.

Endpoints

MéthodePathDescription
GET/healthStatut système (fraîcheur scrape, météo, modèle, zones)
GET/zonesListe des zones configurées
GET/forecast/{zone}Prévision 48 h pour une zone
GET/forecast/{zone}/{horizon_h}Point unique pour un horizon (1, 3, 6, 12, 24, 48)
POST/forecast/triggerDéclenche une nouvelle prédiction pour toutes les zones

Exemples curl

# Vérifier la santé
curl http://localhost:8000/health | jq

# Lister les zones
curl http://localhost:8000/zones

# Prévision Bruxelles 48 h
curl http://localhost:8000/forecast/brussels | jq

# Prévision Paris-Nord à H+6
curl http://localhost:8000/forecast/paris_nord/6

# Déclencher un nouveau run
curl -X POST http://localhost:8000/forecast/trigger

Zones disponibles par défaut

brussels, liege, ghent, amsterdam, paris_nord, luxembourg, cologne, lille.

7. Déploiement Docker Compose

La stack Docker comprend trois services : TimescaleDB + scheduler (scraper + workers) + API.

Étape 1 — Préparer le .env 
cp .env.example .env
# Adapter DATABASE_URL si besoin (par défaut : postgresql://solar:solar_secret@db:5432/solar_forecast)
Étape 2 — Build & run 
docker compose up -d --build
Étape 3 — Vérifier les services 
docker compose ps
docker compose logs -f scheduler
curl http://localhost:8000/health
Étape 4 — Backfill et entraînement initiaux 
docker compose exec scheduler python main.py backfill
# … attendre quelques jours de scrape …
docker compose exec scheduler python main.py train
Sécurité : changer impérativement POSTGRES_PASSWORD dans docker-compose.yml avant tout déploiement hors machine locale.

Volumes

  • pgdata — données PostgreSQL (persistantes)
  • rawdata — tuiles JPEG sat24
  • models — modèles XGBoost sérialisés

8. Tuning Optuna & modèles

Recherche d'hyperparamètres

# 50 trials par défaut, horizon H+1
python main.py tune

# 100 trials sur l'horizon H+6
python main.py tune --horizon 6 --trials 100

Les paramètres explorés : n_estimators, max_depth, learning_rate, subsample, colsample_bytree, min_child_weight, gamma, reg_alpha, reg_lambda.

Le tuning utilise une cross-validation walk-forward à 3 folds, ce qui respecte la nature temporelle des données (jamais de fuite du futur vers le passé).

Le meilleur modèle est sauvegardé dans models/xgboost_v1_tuned.pkl.

Charger un modèle dans son code

from model.trainer import load_models
models = load_models("v1_tuned")  # dict[horizon_h, XGBRegressor]
y_pred = models[6].predict(X)     # prévision H+6

9. Dépannage

Le scrape échoue avec 403 ou 429

  • Vérifier que SAT24_MIN_REQUEST_INTERVAL_S est ≥ 5 secondes (défaut OK).
  • Le User-Agent est défini dans scraper/sat24_scraper.py. Le modifier si besoin.
  • Patienter quelques minutes — le rate-limit côté Infoplaza est temporaire.

train renvoie « No training data »

  • Lancer python main.py backfill (météo) ET attendre que le worker ait traité au moins une journée d'images.
  • Vérifier le contenu de cloud_features en DB : SELECT COUNT(*) FROM cloud_features;
  • Vérifier que les ZONE_PIXEL_BBOXES sont dans les dimensions des tuiles (sinon ROI vide → NaN).

L'API renvoie « No forecast available »

  1. Avoir entraîné un modèle : python main.py train.
  2. Avoir déclenché au moins une prévision : POST /forecast/trigger ou attendre HH:05 si scheduler actif.
  3. Vérifier /health — si status=unavailable, regarder quel champ est None.

Erreur OpenCV sur Linux dans Docker

Si libgl1 manque dans une image custom, l'ajouter au Dockerfile (déjà inclus dans celui fourni).

Logs

Le format global est défini dans main.py :

YYYY-MM-DD HH:MM:SS [LEVEL] module — message

Les niveaux par défaut sont INFO ; passer à DEBUG en modifiant logging.basicConfig(level=logging.DEBUG, ...) dans main.py.
